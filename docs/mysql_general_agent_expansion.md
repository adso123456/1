# MySQL 通用智能问数扩展

## 1. 定位与边界

本次把 `mysql-lzh-monitor` 从 18 表专项试点扩展为经过逐表调查的通用业务问数数据源。水质日报/月报仍是独立的确定性附加能力；普通自然语言问题继续走 `run_sql`，返回真实查询结果和可选图表，不复用报表结果。

本次没有修改 MySQL 数据、表结构、HTTP 路由、SSE/WebSocket 协议或返回结构，也没有把查询结果、数据库文件、Chroma 文件或运行日志提交到仓库。

## 2. 全库调查结论

只读调查覆盖 `lzh_monitor` 的全部 307 个对象（306 张基础表、1 个视图）和 6113 个字段：

| 结论 | 对象数 | 字段数 |
|---|---:|---:|
| 纳入通用问数 | 147 | 3085 |
| 明确排除 | 155 | - |
| 待业务确认 | 5 | - |
| 合计 | 307 | 6113 |

- 原 18 张 B3 表全部保留。
- 对原先未选择的 289 张表逐表记录了类型、字段、索引、外键、估算行数、注释、代码引用、分类、领域、纳入结论、理由和置信度。
- 纳入范围覆盖 15 个业务领域，包括水质、水文、气象、污染源排放、水生态、空间地理、预警、巡查、项目防治、模型计算和社会经济等。
- 备份/历史副本、物理分片、系统框架表、日志、附件媒体、无可靠语义对象和高风险技术对象均未直接开放。
- 发现 45 个敏感或不适合问数的字段；其中纳入表内的 23 个字段通过字段白名单明确排除。

完整逐表结论见 [mysql_full_schema_inventory.md](mysql_full_schema_inventory.md)，机器可读清单见 `config/mysql_full_schema_inventory.json` 和 `config/mysql_general_agent_scope.json`。

## 3. 待确认项

以下 5 张表没有足够证据，因此没有训练为可查询表：

- `wm_waterquality_year_records`：空表，表名为年度记录，但月份字段注释存在语义冲突。
- `yn_s_address_area`
- `yn_s_address_city`
- `yn_s_address_province`
- `yn_s_address_street`

后 4 张地址表缺少注释、代码引用和可验证业务样本。确认业务含义前保持排除。

## 4. 关系、时间与有效数据规则

- 仅训练 14 条 B3 已验证的高置信逻辑关系；数据库中发现但两端未纳入的外键只留档，不供 Agent 使用。
- 未验证的同名 `id`、`name` 不构成 JOIN 依据；小时、日、月事实表不得跨粒度直接拼接。
- 时间范围统一使用左闭右开形式，例如 `>= '2025-07-01' AND < '2025-08-01'`。
- 只有清单中确认的 `del_flag`、状态字段等有效数据规则才能自动加入 SQL。

关系白名单和禁止规则见 [mysql_verified_relationships.md](mysql_verified_relationships.md)。

## 5. Metadata、Memory 与检索

正式发布 revision 3：

- Metadata：147 张表、3085 个字段。
- DDL Memory：147 条。
- 领域分块业务文档：24 条，每块最多 8 张表。
- 经新范围 SQLGuard 重新校验的既有 Tool Memory：18 条。
- Memory 总数：189 条。

发布使用 B5 的候选构建、校验、原子切换与恢复流程。原有 18 条 SQL Tool Memory 未丢失，报表专用 `wm_section_wq_info` 仍不进入通用问数范围。

检索先按业务领域、实体词、粒度和时间意图缩小候选，再把最相关的少量表及其完整字段提供给模型，避免把 147 张表的完整 DDL 一次性塞入上下文。污染源类型、污染源监测、气象实测等易混淆意图增加了确定性领域加权和冲突抑制。

## 6. 真实链路验证

已在独立端口通过真实 Agent/SSE 链路验证：

| 场景 | 真实 SQL 主要表 | 结果 |
|---|---|---|
| 污染源类型统计 | `rs_pollutant_info` | 7 行 + 柱状图 |
| 2025 年 7 月气象降雨 | `wh_meteorological_day_records`、`wm_meteorological_info` | 8 行 + 柱状图 |
| 水文趋势 | 水文日记录及站点表 | 8 行 + 折线图 |
| 污染源分类占比 | `rs_pollutant_info` | 7 行 + 饼图 |
| 污染源监测指标 | `rs_pollutant_day_records` | 3 行 + 柱状图 |
| 明确要求水质日报 | 报表确定性链路 | 返回 `report_result`，不返回普通 DataFrame/图表 |

普通问数场景均未返回 `report_result`。B3 回归首次为 16/17，通过检索消歧修复后，对唯一失败原问题原样重跑通过。

## 7. 验证摘要

- 全库清单一致性：7/7。
- 纳入表只读可达性：147/147；15 个业务领域均有代表表通过 Metadata、SQLGuard 和真实 `LIMIT 1` 检查。
- B5 发布中断恢复：19 个故障注入点及并发、二次中断、路径篡改场景全部通过。
- MySQL 数据源测试：21/21；MySQL Runtime 真实冒烟：9/9。
- PostgreSQL Runtime/工厂回归：23/23、26/26。
- 路由、会话绑定和 Runtime 管理：8/8、30/30、45/45。
- 水质报表规则、日报/月报、API/PDF 回归全部通过。
- 前端生产构建、lint、报表契约和数据源契约测试通过；lint 保留 4 条既有 warning。

## 8. 后续动作
