# 水质报表确认优先对话流程

## 1. 意图与路由

水质日报、月报及泛化“生成报表”必须同时具备生成动作词。普通查询、统计、趋势和表字段问题继续进入通用 Agent，不因出现“日报”或“月报”字样被拦截。

在 PostgreSQL 等错源会话中，仍先返回结构化数据源建议。用户在授权且可用的 `mysql-lzh-monitor` 新会话中自动重发原问题后，只展开配置，不自动生成。

## 2. 确认原则

聊天处理器只读取真实站点配置选项并返回 `report_config`，不访问正式报表数据，不创建快照，不生成 PDF。即使用户已经提供日期、月份、指标、频次和回看范围，也只把它们作为默认值。

只有用户点击“生成预览”后，前端才调用：

```text
POST /api/reports/water-quality/generate
```

该接口创建不可变 `report_id` 快照；结果预览与 PDF 下载始终读取同一快照。

## 3. 配置预填

- 明确日报日期或月报月份时使用该周期；缺失时使用当天或当前月。
- 未明确指标时默认全选真实站点配置指标；明确指标时只预选已匹配项。
- 明确频次只应用于已明确选择且支持该真实频次的指标。
- 日报回看范围只允许近 2—7 日，默认近 3 日；无效值回退近 3 日并显示错误。
- 月报不使用回看范围。
- 泛化“生成报表”默认日报，并显示日报/月报类型选择。
- 未知指标、无效周期和不支持的真实频次仍返回可修正的 `report_config`。

## 4. 前端状态

新产生的 `report_config` 不写入消息历史，而是以 `conversation_id` 为键保存到独立 pending 状态。切换会话、刷新页面后恢复各自草稿；新建会话不继承，删除会话同步清理。数据源停用或不再可用时安全关闭草稿并提示。

发送任何新问题前先关闭当前未确认草稿；若新问题仍是报表请求，新的结构化配置会替换它。点击取消只关闭配置，不调用生成接口。生成失败时面板保持展开，日期、类型、指标、频次和回看范围不丢失。

## 5. ReportComposerPanel

面板固定在 ChatArea 输入框上方，不进入消息滚动区。桌面端紧凑换行，指标与频次面板优先向上展开；窄屏使用底部抽屉。指标摘要显示一个或两个名称，超过两个时显示首项与 `+N`，并支持直接移除已显示项。

频次下拉只显示该指标真实存在的值，默认“按站点配置”；未选择的指标禁止修改频次。日报显示日期与近 2—7 日，月报显示月份并隐藏回看范围。

## 6. 结果与重新生成

确认成功后清除 pending 配置，把 `report_result` 作为正式助手消息追加到当前会话并滚动到结果卡。结果卡保留预览入口，并提供“修改配置重新生成”：

1. 保留旧结果和旧 `report_id`；
2. 读取最新真实指标选项；
3. 用旧结果参数创建新的 pending 配置；
4. 用户再次确认后生成新的 `report_id`。

## 7. Widget 与旧历史

主工作台和 Widget 共用 ChatArea 与 ReportComposerPanel。Widget 不增加数据源管理入口，继续受嵌入 Token 的 `allowed_source_ids` 限制，并使用 Widget 主题色。用户界面不渲染内部 `source_id`。

旧历史中的 `report_config` 消息仍由 `ReportConfigCard` 兼容展示和生成；无需迁移旧 localStorage。新配置一律不再写成伪消息。

## 8. 已知限制

- 报表能力当前固定依赖 `mysql-lzh-monitor` 的真实站点配置。
- 本流程不改变报表 SQL、日报/月报计算公式或 PDF 模板。
- 完整长表仍只在应用内预览 iframe 中展示。
